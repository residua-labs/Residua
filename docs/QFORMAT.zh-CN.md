# QFORMAT — 带类型的内容地址，版本 1

[English](QFORMAT.md) | 中文

## 目的与范围

Residua 以 *q*（带类型的内容地址）命名不可变内容。本文档是该地址
版本 1 的规范：在用的两种地址（`digest` 与 `q`）、哈希原像的语法、
打印形式与二进制形式、类型注册表，以及每个比较点遵守的规则。它约束
本版本中每一个以 `sha256:` 打印的字段——构件表、存储键、回执、
清单——以及 `release/checks/qformat/` 中的一致性向量。该批次在设计与
测量时所依据的工作文档保留在仓库内（`reports/qformat/`）；本文件是
其发布形式。

## 动机

内容地址使一方能够在不信任产出者的前提下复用结果，因为名称由内容
重新计算得出。该方案成立的前提是：两种不同类别的内容绝不能共享同
一个名称。在本规范之前，树中每个身份都是其字节的原始 SHA-256 摘要。
一次实测清点（349 处哈希站点，其中 213 处是身份）发现了七个具体的
碰撞：某一种含义的字节与另一种含义的字节哈希到同一个值——例如七
字节文件 `5:hello` 与 S-表达式原子 `hello` 共享了同一个地址。一个能
被两个类别共享的地址不是地址。修复方法不是换哈希函数，而是带类型的
原像：把类别写入被哈希的字节，使同样字节在两个类别下按构造必然产生
不同的地址。

## 两种地址

**digest** —— `digest(b) = SHA-256(b)`，原始字节，不加头部。
角色：文件完整性与互操作；它与 `sha256sum` 的输出完全一致。
digest 绝不是身份，也绝不出现在需要 `q` 的位置。

**q** —— `q(kind, c) = SHA-256(header ++ c)`，其中 `header` 是下文的
原像语法，`c` 是该类别的规范字节串。角色：带类型的身份。
"含义相等则 q 相等"在*类别内部*成立。同样字节在两个类别下产生不同
的 q——恒成立，由构造保证——而非巧合。

## 原像语法

    preimage := kind SP len NUL canonical
    kind     := [a-z][a-z0-9-]*          （至多 32 字节，取自注册表）
    len      := canonical 的十进制字节长度，无前导零；
                空 canonical 为 "0"
    NUL      := 0x00

头部正是 git 对象头约定 `<type> <len>\0` [^1]，只是类型取自注册表而
非固定集合。`len` 使头部自我终止；`kind` 中的任何字节都不可能是
`SP` 或 `NUL`。

对每个版本 1 类别，`canonical` 就是产生站点此前哈希的那个字节串——
编码、长度前缀与容器标签原样保留在 canonical 字节内，不改变。本批次
只改变了原像：`SHA-256(b)` 变为 `SHA-256(header ++ b)`。没有任何编解码、
记录布局或序列化发生变化。

## 表示形式

| 场合 | 形式 |
|---|---|
| 打印文本字段（清单值、[回执](GLOSSARY.zh-CN.md)绑定、表、日志） | `sha256:` + 64 位小写十六进制，digest 与 q 同式 |
| 路径段与文件名 | `sha256-` + 64 位十六进制 |
| 自描述二进制（无外围模式存储的 q） | multihash `0x12 0x20` + 32 字节（共 34 字节）[^2] |
| 模式定型的记录内部 | 32 个原始字节；算法与类别由模式承载 |

打印出的 `sha256:<hex>` 本身并不区分 `digest` 或 `q:<kind>`——由它
所在的字段区分。每个承载内容地址的字段、记录槽、路径命名空间和存储
都是定型的：`digest`，或注册表中某个类别的 `q:<kind>`。

## 类别注册表，版本 1

注册表只增不改：一个类别字符串一旦用于已发布的原像，就绝不改变
用途；规范形式若需变化，则是新的类别。*exclusions* 列登记规范形式所
省略的输入（公开各类别哈希输入排除表的对等设计规则）；版本 1 各类别
无排除项——其字节已是规范的序列化形式。

| 类别 | 规范形式 | 排除项 |
|---|---|---|
| `blob` | 原始内容字节 | 无——字节即内容 |
| `rsx-atom` | `itoa len ++ ":" ++ atom` | 无 |
| `rsx-list` | `"(" ++ "32:q₁" … ++ ")"` | 无 |
| `nf-key` | `NF1 ++ stage ++ node-q ++ sigQ ++ ctx ++ compiler ++ profile` | 无 |
| `nf-ctx` | encLL 上下文字节 | 无 |
| `nf-profile` | encList layI ++ profile 标量 | 无 |
| `nf-sig` | encList 签名 | 无 |
| `nf-node` | encList 节点字节 | 无 |
| `rval` | encodeRVal 的输出（保留 `RVAL\x01` 于内部） | 无 |
| `receipt` | canonOpen / canonStep 字节 | 无 |
| `verdict` | 十个判定字段的 RVAL 记录：主体 kind+q、命题 q、公理集 q、理论轮廓 q、观察 q、实例上下文 q、环境 q、检查器 q、策略 q、信任切 q | 无——十字段全部参与哈希 |
| `decl-line` | 一行声明的字节 | 无 |
| `decl-bundle` | 拼接行字节 | 无 |
| `text` | 定长 UTF-8 文本字节 | 无 |
| `gate` | 语法门字节流 | 无 |
| `cwasm-key` | `wasmQ ++ 0 ++ hostQ` | 无 |
| `scc` | 保留：`"(" ++ n ++ (":" ++ i ++ ":" ++ len(cᵢ) ++ ":" ++ cᵢ)* ++ ")"`——成员数，随后每成员依次为十进制下标、字节长度与规范字节，按该组已发布的规范顺序 | 各成员类别自身的排除项作用于各 `cᵢ` |

原始字节内容的身份一律是 `blob`，无论字节位于何处——类别说明的
是如何解释字节，而不是哪个程序写出了它们。仅当被哈希的字节在哈希
时被构造为规范序列化，才存在 `blob` 以外的类别。

## 比较规则

每个重算 q 的验证器都携带期望类别：`hashOk kind`、
`verifyObject kind`、`cacheHit kind`。存储的类别按其部署的命名空间
声明，条目以该命名空间类别的 q 寻址。读者应知的两个推论：

- 一个字节恰好等于某个合法带类型原像的文件（例如 18 个字节
  `"rsx-atom 7\x005:hello"`），其 digest 与 `q(rsx-atom, "5:hello")`
  数值相同。这无法避免也并无危害：digest 因互操作而按字节精确，而
  比较点在期望 `q:rsx-atom` 的位置拒绝 digest 字段。
  `release/checks/qformat/` 中的发布向量恰好演示了这一对。
- 两个存有相同字节的 `blob` 存储对同一个 q 作答。这是设计使然：
  q 命名的是内容，而不是持有它的存储。

内部化规则（不变）：内存中哈希只是查找键，命中在使用前以原像的
结构相等确认——带类型的原像使该确认包含头部。

## 互递归组（保留）

强连通分量作为整体哈希与检查：每组一个 `q(scc, …)`，成员规范字节
按已发布的规范顺序并带成员下标——绝不使用让成员互相证明的逐成员
q。`scc` 已在注册表中保留；成员顺序随规范 SCC 编码的落地而公布。
在此之前任何产出者不得发出 `scc` 原像。

## 三种身份保持区分

`q`（带类型的内容身份）、快照切点、跨编辑的持久句柄是三个不同的
名字。字段与协议绝不互相替代。本规范只约束 `q`。

## 校验一个已发布的 q

本版本中任何 `q:<kind>` 只需 `sha256sum`、`printf`、`cat` 即可重算：

```sh
{ printf '%s %d\0' "<kind>" "$(wc -c < bytes | tr -d ' ')"; cat bytes; } \
  | sha256sum
```

`release/checks/qformat/` 提供五个类别的锚定向量，以及植入的对照
（类别分离、digest–q 边界、上文的手工原像案例），每条都附有产生它
的命令与期望输出。

## 信任假设与限制

- 假定 SHA-256 的抗碰撞性 [FIPS 180-4]；定型由原像与字段模式承担，
  不由打印形式承担。
- 注册表为版本 1 且只增不改；规范形式需要变化的类别是新类别，因此
  已发布的 q 永不漂移。
- `scc` 已保留但尚无产出者（成员顺序未发布）。
- `sha256:` 字段只在算法标签意义上自描述；类别由字段的声明类型
  承载，因此两个声明类别不同的字段即使打印相同十六进制，也是不同
  的地址，而非同一个。
- digest 字段为互操作保持原始 SHA-256；只有身份字段携带头部。
